## How Theming Works

Every visual value in Nika lives in one file: `nika-tokens.css`. Running `npx nikaui init` copies it next to your global stylesheet and adds an `@import` for it — components never hard-code a color, they only use the Tailwind utilities the file maps at the bottom.

The file is yours from the moment it's written. Edit it, delete it, or replace it outright — the only requirement is that the closing `@theme inline` block keeps mapping the same utility names Nika's components use (`bg-primary`, `text-content`, `border-line`, and so on).

### The `--nika-` prefix

Every custom property Nika defines is prefixed **`--nika-`** — `--nika-primary`, `--nika-canvas`, `--nika-radius`. This is deliberate: it's how the token layer avoids colliding with a `--primary` you (or another tool) might already have in scope.

The Tailwind utility classes generated *from* those variables are **not** prefixed: `bg-primary`, `text-primary-fg`, `rounded-lg` stay exactly as short as any other Tailwind class. The mapping between the two happens once, in a `@theme inline` block:

```css
/* nika-tokens.css */
:root {
  --nika-primary: oklch(0.705 0.188 47);
}

@theme inline {
  --color-primary: var(--nika-primary);
}
```

```tsx
// Your components — always the unprefixed utility
<div className="bg-primary text-primary-fg" />
```

So: you **theme** by editing `--nika-*` in `nika-tokens.css`, and you **consume** through the unprefixed Tailwind class. Redefining `--primary` (no `nika-` prefix) does nothing — nothing in the token layer reads that name.

## Dark Mode

`:root` carries the light palette; a `.dark` class anywhere above the element (typically `<html>`) switches to the dark one:

```html
<html class="dark">
```

Canvas, surface, content, and line colors all have a `.dark` override. The five accent colors below are theme-invariant — the same hue in light and dark — so the brand reads consistently either way.

## Accents

Five accent blocks are keyed by the `data-accent` attribute, set on any ancestor element (usually `<html>`). `sun` is the default and applies with no attribute present at all — you only need `data-accent` to opt into one of the other four:

```html
<html data-accent="violet">
```

| Accent | `data-accent` value | Character |
| --- | --- | --- |
| Sun (default) | *(none, or)* `sun` | warm gold/orange |
| Violet | `violet` | purple |
| Emerald | `emerald` | green |
| Azure | `azure` | blue |
| Rose | `rose` | red-pink |

Each accent block sets `--nika-primary`, `--nika-primary-hover`, `--nika-primary-press`, `--nika-primary-fg`, `--nika-accent`, and `--nika-ring`.

## Customizing Colors

Change the theme by editing the `--nika-*` values in your copy of `nika-tokens.css` — never by adding an unprefixed variable of your own. For example, to change the default (`sun`) accent's primary color:

```css
/* nika-tokens.css */
:root,
[data-accent="sun"] {
  --nika-primary: oklch(0.64 0.2 260); /* now blue instead of gold */
  --nika-primary-hover: oklch(0.68 0.19 260);
  --nika-primary-press: oklch(0.59 0.2 258);
}
```

Because the `@theme inline` block references `var(--nika-primary)` rather than copying its value, every utility built from it — `bg-primary`, `ring-primary`, `text-primary` — picks up the change immediately, including on already-rendered elements, with no rebuild required.

## Available Tokens

### Surface & content

| Token | Used for |
| --- | --- |
| `--nika-canvas` | Page background |
| `--nika-canvas-2` | Secondary page background |
| `--nika-surface` | Card/panel background |
| `--nika-surface-2` | Secondary surface background |
| `--nika-overlay` | Modal/popover backdrop surfaces |
| `--nika-muted` | Muted/subdued backgrounds |
| `--nika-code` | Code block background (stays dark in both themes) |
| `--nika-content` | Default text color |
| `--nika-content-muted` | Secondary text color |
| `--nika-content-subtle` | Tertiary/placeholder text color |
| `--nika-line` | Default border color |
| `--nika-line-strong` | Emphasized border color |

### Primary & accent

| Token | Used for |
| --- | --- |
| `--nika-primary` | Primary brand color |
| `--nika-primary-hover` | Primary, hover state |
| `--nika-primary-press` | Primary, pressed/active state |
| `--nika-primary-fg` | Text/icon color on top of primary |
| `--nika-accent` | Secondary accent color |
| `--nika-ring` | Focus ring color |

### Semantic

| Token | Used for |
| --- | --- |
| `--nika-success` | Success state |
| `--nika-warning` | Warning state |
| `--nika-danger` | Error/danger state |
| `--nika-danger-fg` | Text/icon color on top of danger |
| `--nika-info` | Informational state |

These don't change between light and dark — one hue reads correctly on both canvases.

### Radius

| Token | Used for |
| --- | --- |
| `--nika-radius` | Base radius (`0.7rem`); every other radius token derives from this one |
| `--nika-radius-sm` / `-md` / `-lg` / `-xl` / `-2xl` | Scaled radii |
| `--nika-radius-full` | Fully rounded (pills, avatars) |

### Type, shadow & motion

| Token | Used for |
| --- | --- |
| `--nika-font-sans` | Default sans-serif stack (system fonts — Nika ships no web font) |
| `--nika-font-mono` | Monospace stack |
| `--nika-shadow-color` | Base hue/saturation/lightness the shadow tokens below tint their opacity against |
| `--nika-shadow-sm` / `--nika-shadow` / `--nika-shadow-lg` | Box shadows |
| `--nika-glow` | Focus/emphasis glow around primary-colored elements — applied directly as a `box-shadow` value, not through a mapped utility |
| `--nika-ease-spring` / `-out` / `-snap` / `-inout` | Easing curves |
| `--nika-duration-fast` / `--nika-duration` / `-slow` / `-spring` | Animation durations — Tailwind v4 has no duration theme namespace, so these aren't mapped to a utility; read `var(--nika-duration-*)` directly |

Most tokens above are mapped to a same-purpose Tailwind utility (`--nika-primary` → `bg-primary`/`text-primary`/etc., `--nika-radius-lg` → `rounded-lg`) through the `@theme inline` block at the bottom of `nika-tokens.css`. `--nika-shadow-color`, `--nika-glow`, and the duration tokens are the exceptions — they have no Tailwind utility and are meant to be read as CSS variables directly.
