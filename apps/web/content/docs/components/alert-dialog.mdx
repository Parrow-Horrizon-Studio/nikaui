## Usage

```tsx
import {
  AlertDialog,
  AlertDialogContent,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogCancel,
  AlertDialogAction,
} from "@/components/ui/alert-dialog"

const [open, setOpen] = useState(false)

<AlertDialog open={open} onClose={() => setOpen(false)}>
  <AlertDialogContent>
    <AlertDialogHeader>
      <AlertDialogTitle>Delete project?</AlertDialogTitle>
      <AlertDialogDescription>
        This permanently deletes acme-production and everything in it.
      </AlertDialogDescription>
    </AlertDialogHeader>
    <AlertDialogFooter>
      <AlertDialogCancel onClick={() => setOpen(false)}>Cancel</AlertDialogCancel>
      <AlertDialogAction onClick={onDelete}>Delete</AlertDialogAction>
    </AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>
```

## Alert dialog or dialog?

An alert dialog interrupts to ask about something consequential and usually
irreversible. It is not for a form or a detail panel — reach for
[Dialog](/docs/components/dialog) there.

The practical difference is that an alert dialog should not be dismissible by
clicking away. A stray click should not be able to answer a question about
deleting something.

## Destructive intent

```tsx
<AlertDialogContent intent="danger">
  {/* … */}
</AlertDialogContent>
```

`intent="danger"` gives the dialog a warning icon and turns the confirm button
into a danger button. Without it, "Delete" renders in the brand accent — the
same colour as every ordinary primary action on the site, which is exactly
wrong for the one button you want the reader to pause before pressing.

## Sizes

```tsx
<AlertDialogContent size="sm" />
<AlertDialogContent size="md" />
```

## Writing the copy

The title should ask the question, and the confirm button should name the
action:

- Good: "Delete project?" with buttons "Cancel" and "Delete"
- Bad: "Are you sure?" with buttons "No" and "Yes"

A reader skimming sees the buttons before the prose. "Yes" tells them nothing
about what they are agreeing to.

## Focus

Focus moves into the dialog on open and returns to whatever opened it on close.
Escape closes it. If the action is genuinely destructive, put focus on Cancel
rather than the confirm button.

## Customization

```tsx
<AlertDialogContent className="max-w-md" />
```

## API Reference

### AlertDialog

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | — | Whether the dialog is shown |
| `onClose` | `() => void` | — | Called on Escape or backdrop dismissal |

### AlertDialogContent

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg" \| "full"` | `"md"` | Panel width |
| `intent` | `"default" \| "danger"` | `"default"` | Danger adds a warning chip and a danger confirm button |
| `motion` | `"none" \| "snap" \| "glide" \| "spring" \| "bounce"` | inherits | Animation feel |
