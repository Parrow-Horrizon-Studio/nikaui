## Installation

```bash
npx nikaui add alert
```

## Usage

```tsx
import { Alert, AlertTitle, AlertDescription } from "@/components/ui/alert"

export default function Example() {
  return (
    <Alert>
      <AlertTitle>Heads up</AlertTitle>
      <AlertDescription>
        This is what a default alert looks like.
      </AlertDescription>
    </Alert>
  )
}
```

`Alert` sets `role="alert"` itself, so assistive technology announces the
message as soon as it appears.

## Variants

```tsx
<Alert variant="default">Default</Alert>
<Alert variant="success">Success</Alert>
<Alert variant="warning">Warning</Alert>
<Alert variant="danger">Danger</Alert>
<Alert variant="info">Info</Alert>
```

## Icons

An `<svg>` placed as a direct child of `Alert` is pulled into the left gutter
and the title and description indent to clear it. In the `success`, `warning`,
`danger` and `info` variants the icon also takes that variant's colour; under
`default` it inherits the surrounding text colour.

```tsx
<Alert variant="warning">
  <TriangleAlertIcon />
  <AlertTitle>Storage almost full</AlertTitle>
  <AlertDescription>You have used 92% of your quota.</AlertDescription>
</Alert>
```

## Dismissible

```tsx
<Alert variant="warning" onDismiss={() => setShown(false)}>
  <AlertTitle>Quota at 90%</AlertTitle>
</Alert>
```

The close button carries an accessible name. A bare glyph is invisible to a
screen reader, which is the usual way this button ships broken.

## With an action

```tsx
<Alert variant="danger" action={<Button size="sm">View logs</Button>}>
  <AlertTitle>Deploy failed</AlertTitle>
  <AlertDescription>Build exited with code 1.</AlertDescription>
</Alert>
```

"Something failed" almost always wants "and here is what to do about it".

## The rail

Status is carried by a rail down the edge and an icon chip, over an opaque
surface — not by tinting the surface itself. A translucent status surface lets
page content show through and become unreadable, which looks fine on a plain
background and fails over a photograph.

```tsx
<Alert variant="danger" rail="top">…</Alert>
```

## Customization

Two routes. `className` merges with the component's own classes:

```tsx
<Alert className="rounded-none border-x-0" />
```

The token layer changes every instance at once and survives a component
update:

```css
:root {
  --nika-danger: /* your value */;
}
```

Prefer tokens. A `className` override applies to one call site; a token
change applies to the whole library, which is what keeps it coherent.

## API Reference

### Alert

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `"default" \| "success" \| "warning" \| "danger" \| "info"` | `"default"` | Visual style variant |

`Alert` renders a `<div>` and forwards its ref, so it also accepts every
standard `div` attribute — `id`, `className`, `onClick` and the rest.

### Sub-components

- `AlertTitle` — renders an `<h5>`; accepts every standard heading attribute
- `AlertDescription` — renders a `<div>`; accepts every standard `div` attribute

Neither sub-component adds props of its own; both forward their ref.
